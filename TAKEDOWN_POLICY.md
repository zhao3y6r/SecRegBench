# Rights, privacy, and takedown policy

The maintainers aim to distribute only synthetic benchmark content, public
source metadata, derived rule representations, reproducibility code, and
sanitized experimental results.

## What to report

Please report any credible concern involving:

- copyrighted or database-protected content reproduced beyond source metadata,
  citation, or short locators;
- personal or confidential information;
- credentials, private infrastructure details, or raw model requests/responses;
- licensing conflicts or missing attribution;
- a harmful or materially unsupported regulatory label.

## How to report

Use the repository's **Rights or data issue** template. Include:

1. the exact file path and, if applicable, scenario or source ID;
2. the public URL or other evidence identifying the relevant source;
3. the nature of the rights, privacy, or factual concern;
4. the requested correction, attribution, restriction, or removal;
5. a way for maintainers to request clarification.

Do not place passwords, API keys, private customer information, identity
documents, or other secrets in a public issue. For sensitive security matters,
follow [SECURITY.md](SECURITY.md).

## Response process

For a credible report, maintainers will:

1. acknowledge and scope the report;
2. preserve the affected release hash and audit trail;
3. temporarily restrict or remove the affected file or release when reasonably
   necessary to reduce harm;
4. investigate source, transformation, and license records;
5. publish a corrected version, attribution, limitation, or reasoned response;
6. avoid silently overwriting an already published hash.

Submitting a report does not itself establish infringement, liability, or a
particular legal remedy. This process is intended to support prompt,
good-faith review.
